Mango QA auditeur de code autonome
Revue de code automatisée

Il vous dit ce qu'il n'a pas lu.

Tous les auditeurs de code rendent un verdict. Mango QA est le seul qui déclare le périmètre sur lequel ce verdict porte — combien de fichiers il a réellement envoyés au modèle, et lesquels il a laissés de côté.

Un feu vert sur une fraction du code n'est pas un feu vert. Un feu vert rendu par un cerveau qui n'a rien pu juger non plus. C'est le mensonge par omission que ce produit existe pour rendre impossible.

Pourquoi

Vous produisez du code plus vite que vous ne le relisez.

C'est le vrai changement des deux dernières années, et il a un effet de bord : la relecture est devenue le goulot. Alors on la délègue à un modèle — et on hérite d'un problème plus discret que celui qu'on voulait résoudre.

Le silence est indétectable

Un relecteur automatique lit une partie de votre code, puis rend un verdict sur le tout. Un vrai défaut situé dans la partie non lue produit un feu vert — et rien, nulle part, n'indique que l'audit était partiel.

Un faux positif se voit. Une omission, non.

Quand l'outil crie au loup, vous le constatez et vous l'ignorez. Quand il se tait sur ce qu'il n'a pas regardé, vous n'avez aucun moyen de le savoir. Le second cas est celui qui coûte cher.

« Rien trouvé » ≠ « rien à trouver »

Ces deux phrases sont différentes et la plupart des outils les rendent identiques. Mango QA les distingue partout : dans le prompt envoyé au modèle, dans le rapport, dans le verdict, et dans sa sortie machine.

Un auditeur a le droit de ne pas tout lire.
Il n'a pas le droit de le taire.

Pour qui

Pour qui sait lire un verdict d'audit.

Mango QA ne remplace pas votre jugement, il vous donne de quoi l'exercer. Il s'adresse donc d'abord à ceux qui savent quoi faire d'un « feu rouge, branche sécurité, injection SQL ligne 40 ».

Cœur de cible

Le développeur solo

Vous générez beaucoup, vous relisez seul, personne ne vous fait de revue. Mango QA est le deuxième regard que vous n'avez pas — un processus séparé, qui dit rouge même quand le générateur dit « terminé ».

Deuxième vague

L'agence, le freelance

Vous livrez du code à des clients et vous engagez votre nom dessus. Un rapport qui déclare son périmètre est un rapport que vous pouvez joindre à une livraison sans risquer de promettre plus que ce qui a été vérifié.

Intégration

Votre CI, votre assistant

Un code de sortie par situation, un serveur MCP pour brancher l'auditeur dans Claude Code ou tout client compatible. La couverture y est un champ obligatoire : un assistant ne peut pas relayer un verdict sans son périmètre.

Comment

Une commande, et il est branché.

L'installation pèse 1,1 Mo. mangoqa init pose les trois portes — votre assistant, votre git push, votre CI — et ne remplace jamais une configuration existante : elle est fusionnée, ou laissée intacte.

# installer, puis brancher (MCP + hook pre-push + action de CI)
$ npm i -g mango-qa
$ mangoqa init --hook --ci
# auditer ce qui a changé — le mode à privilégier
$ mangoqa . --diff
# le code fait-il ce qui était demandé ?
$ mangoqa . --diff --spec #42
# en intégration continue : refuser un feu vert partiel
$ mangoqa . --json rapport.json --exiger-couverture

Sept branches d'audit spécialisées — spec, architecture, sécurité, accessibilité, performance, tests, design system — chacune avec son propre périmètre de fichiers et sa propre couverture déclarée. La branche spec ne juge pas le code : elle juge le travail, et ne s'allume que si vous lui dites ce qui était demandé.

Codes de sortie

0

Feu vert. Aucune branche bloquante en échec.

1

Feu rouge. Une branche bloquante a trouvé un défaut concret, avec son correctif.

2

Erreur d'usage. Dossier introuvable, option inconnue. Jamais un défaut d'audit — votre CI ne confondra pas les deux.

3

Feu vert sur lecture partielle, avec --exiger-couverture. Distinct du rouge : aucun défaut n'a été trouvé. On refuse seulement de traiter « rien vu » comme « rien à signaler ».

4

Non vérifié. Une branche bloquante n'a pas pu juger — le cerveau n'a pas répondu, ou pas dans le contrat. Ni vert ni rouge : il n'y a pas de verdict. Ce code n'est pas désactivable — une lecture partielle est un mode dégradé qu'on peut assumer, une absence de jugement n'est pas un audit.

Ce qu'on a mesuré

Nous publions notre propre taux d'erreur.

Sortir un auditeur dont on ignore le taux d'erreur serait exactement la faute qu'on reproche aux générateurs de code. Mango QA est évalué contre un corpus de 32 cas étiquetés — des défauts réels, injectés et localisés, plus 8 contrôles propres dont le seul rôle est de faire apparaître nos fausses alertes. Le motif a été vérifié à la main. La branche a signalé un saut de niveau de titre (des h3 sans h2 intermédiaire) — et elle avait factuellement raison : ce n'est pas une hallucination. C'est notre corpus qui déclarait ce fichier « propre en accessibilité » alors qu'il avait été écrit comme un contrôle de tout autre chose. Nous n'avons pas retiré l'étiquette après coup : corriger un corpus juste après avoir vu un résultat défavorable ruine une mesure, même quand c'est défendable. Le chiffre publié est celui mesuré contre le corpus tel qu'il était.

  • →Chaque défaut a un jumeau propre. Le même fichier, à une ligne près. Sans lui, un outil qui crie au loup sur tout code long afficherait 100 % de détection.
  • →Le défaut est enfoui dans le dernier tiers du fichier, jamais en tête.
  • →Les motifs sont vérifiés à la main. Un verdict juste peut l'être pour la mauvaise raison — nous lisons ce que la branche a cité, pas seulement si elle a dit « fail ».
  • →Une panne n'est pas une faute — et n'est pas non plus effacée. Quand le cerveau ne répond pas, l'appel sort des dénominateurs de qualité et s'affiche dans sa propre colonne. Le fondre dans les abstentions noircissait le score ; le taire l'aurait flatté.

Ce que cette mesure n'établit pas

  • →Un corpus, un modèle, une machine, deux passes. Ces chiffres disent que l'auditeur discrimine sur ce corpus. Ils ne prédisent pas son comportement sur votre code.
  • →Le corpus est écrit par nous. Les défauts sont réalistes et vérifiés à la main, mais ils sont injectés — pas récoltés dans la nature.
  • →L'axe « conventions » n'a pas encore trouvé de vrai dépôt à conventions de code, et l'axe « spec » n'a jamais été confronté à un vrai ticket, bavard et ambigu. Les deux mécanismes sont prouvés ; leur valeur ne l'est pas.

C'est écrit ici pour la même raison que la couverture est écrite dans le verdict. Un outil qui vous demande de ne pas croire les logiciels sur parole ne peut pas vous demander de le croire sur parole. Le registre complet de ce que nous ne savons pas encore vit dans FAILLES.md, à côté du code.

Quatre déclarations

Il vous dit toujours sur quoi porte son verdict.

Chacune de ces quatre lignes est née d'un défaut réel, trouvé en exécution sur du vrai code — pas d'une relecture. Et chacune obéit à la même règle de conception : rien d'optimiste n'est jamais une valeur par défaut.

Couverture — ce qu'il a lu

Combien de fichiers sont réellement partis au modèle, et lesquels ont été laissés de côté. Non mesuré n'est jamais rendu comme « tout lu ».

Jugement — ce qu'il a pu juger

Un cerveau qui ne répond pas, ou pas dans le contrat, ne produit plus un feu vert. Il produit NON VÉRIFIÉ, et un code de sortie à part.

Conventions — contre quelles règles

Il lit les règles que votre dépôt a écrites et cite le fichier et la ligne. Un dépôt qui n'en documente aucune s'entend le dire, plutôt que de se voir reprocher des règles que personne n'a écrites.

Spec — contre quelle demande

Le code fait-il ce qui était demandé ? Ce qui manque bloque et cite l'exigence entre guillemets ; ce qui déborde est signalé sans bloquer. Sans spec fournie, il le déclare au lieu d'inventer.

Rien trouvé n'est pas rien à trouver.
Et « pas pu juger » n'est pas « rien trouvé ».

1,1 Mo

Installation minuscule

Mesuré le 8 août 2026 dans un dossier vierge : 1,09 Mo, dépendances comprises. Les paquets lourds — SDK, moteurs d'analyse syntaxique — sont optionnels et ne s'installent que si vous les demandez.

Indépendant du générateur

Ce n'est pas un auto-contrôle. C'est un processus séparé, qui n'obéit ni au modèle qui a écrit le code, ni à l'agent qui l'appelle. Aucun outil MCP exposé ne permet de lui dire « ignore ce constat ».

Souverain, si vous le voulez

--cerveau ollama fait tourner l'audit sans qu'un octet de votre code quitte la machine, et QA_LOCAL_ONLY=on interdit tout repli distant. C'est une option assumée — pas le réglage par défaut, parce qu'un modèle local rend des verdicts moins sûrs et que nous préférons le dire.
